# 04 构建流程详解

## 1. 四种命令

```
sudo ./build.sh            # 全量构建 (无进度标记) 或断点续跑 (有 .build_progress)
./build.sh config          # 强制弹出配置选择菜单 (写 .config 符号链接)
sudo ./build.sh resume     # 交互菜单选续跑起点, 该步之前的复用快照不重跑
sudo ./build.sh clean-pool # 卸载并删除 btrfs 快照池 (快照与断点全部失效)
```

- 参数白名单校验: 传错参数 (如 `resum`) 直接报错, 不会静默当成全量构建
  (全新构建会清空快照池, 误触发代价大);
- 必须 root: 防止非 root 运行写出幽灵进度标记。

## 2. main() 的执行顺序

| 序 | 函数 | 作用 |
| --- | --- | --- |
| 前置 | `configure` | 缺 .config 或显式 config 时弹菜单, `ln -sf` 重设链接 |
| 前置 | source .config | 打印当前配置 / 基础包 / 功能组 |
| 前置 | `check_permission` | 必须 root |
| 0.5 | `sync_firefly_repo` | 以工作区属主身份同步 firefly-reprepro 子模块到远端最新 (失败仅警告) |
| 1 | `pre_base` | 准备基础包 + 快照池初始化/回滚 (见 §3) |
| 1.5 | `start_local_repo_server` + `inject_chroot_hosts` | 本地 firefly 源加速 (见 §5) |
| 2 | `change_apt_source` | 把 `res/$SPACE_NAME/ubuntu.sources` 拷入 rootfs (幂等) |
| 3 | `do_list` | chroot 执行器: 按 DO_LIST 跑功能组, 每步成功打快照 (见 §4) |
| 4 | `do_clean` | 清理与还原 (见 §6) |
| 5 | `do_package` | 打包 ext4 镜像 (见 §7) |
| 收尾 | 清进度标记 | 构建成功自动清 `.build_progress` (快照池保留, 可 resume 复用) |

## 3. pre_base 与 btrfs 快照池

```
output/btrfs_pool.img        稀疏 btrfs loop 池 (16G 起, 剩余<2G 自动扩 8G, 上限 48G)
output/btrfs_mnt/
  ├─ base/                   第 0 层: 基础包解包产物 (构建期只读)
  ├─ work/                   当前构建工作子卷 (= 将来镜像的根, $WORK_DIR)
  └─ snap/<步骤全名>/         每步成功后的只读快照 (COW 零拷贝, 秒级)
```

- **全新构建** (无进度标记): 删旧池 → 建池 → 解包基础包到 base → snapshot 出 work
  → 写进度 `000_pre_base` (解包数分钟, 此后断电无需重新解包);
- **断点恢复** (有合法标记): 挂池 → 从"最后完成步骤"的快照重建可写 work (脏 work
  整体丢弃, 半成品 dpkg 状态被彻底清除) → 从下一步继续;
- **标记非法** (空/多行/步骤不在当前序列): 明确报错退出并给指引, **绝不静默当全新构建**;
- 恢复锚点为 `000_pre_base` 时从 base 子卷重建。

## 4. do_list — chroot 执行器 (核心)

1. 把 `chroot/$SPACE_NAME` + `chroot/scripts/` 拷到 work 内 `/chroot/` (chroot 内执行);
2. DO_LIST 展开为 STEP_SEQ 数组; 组目录不存在 → 显式报错;
3. 每步执行前检查池空间; 按后缀分派 (.apt/.shell/.overlay, 见 03 §3);
4. 步骤在后台执行, 前台只显示 spinner; 全部输出重定向 `output/log/log_<ts>/log`;
5. 步骤成功 → `btrfs subvolume snapshot -r` 打快照 → 更新进度标记 → 下一步;
   **快照失败则中止构建** (失去回滚能力的构建不继续);
6. 步骤失败 → 报错退出; 脏 work 下次构建整体丢弃重试本步。

## 5. 两个加速机制 (默认开, config 可关)

### 本地 firefly 源 (LOCAL_FIREFLY_REPO=1)
```
宿主: python3 -m http.server 80 --bind 127.0.0.1 --directory src_deb/firefly-reprepro
rootfs: /etc/hosts 注入 "127.0.0.1 wiki.t-firefly.com"
效果: libmali/mpp/gstreamer-rockchip 等大包走本地镜像, URL/GPG 验签不变
生命周期: 构建结束/中断自动停服务还原 hosts; 80 端口被占则报错
```

### apt 下载缓存 (LOCAL_APT_CACHE=1)
```
bind-mount: output/apt_cache/archives ⇄ work 内 var/cache/apt/archives
安全性: apt 按 包名_版本_arch.deb 精确文件名取用并校验 SHA256, 不会用旧包顶替
do_clean 用 apt-get autoclean (保缓存) 而非 clean
```

## 6. do_clean — 还原构建痕迹 (顺序敏感)

1. 卸 apt 缓存 bind-mount (失败 → 中止);
2. 按 `DSH_LOCAL_REPO_MARKER` 标记删除 hosts 注入行;
3. 删 work 内 `etc/resolv.conf`、`/chroot`;
4. chroot 内 `apt-get autoclean`;
5. `ln -sf /run/systemd/resolve/resolv.conf /etc/resolv.conf` (还原 resolved 布局);
6. `tools/mount-rootfs.sh -u` 卸 proc/sys/dev/pts。

注: qemu-aarch64-static 目前**保留**在产物中 (删除行被注释)。

## 7. do_package — 打包

```
IMG_SIZE = du -sb work × 1.2            # 20% 冗余
写 /etc/ffgo/ffver: FIREFLY: <commit前10位> / DATE / AUTHOR: user@host
dd seek 稀疏建文件 → mkfs.ext4 → loop 挂载 output/mnt/ → cp -a → umount
产物: output/<IMAGE_NAME>-<YYYYMMDD>-<HHMM>.img
```

## 8. trap 体系 (lib.sh 末尾注册)

| Trap | 行为 |
| --- | --- |
| `ERR` (set -E 继承进所有函数) | 打印失败命令与行号 → 清理 → 退出 1 |
| `INT`/`TERM`/`HUP` | Ctrl+C / kill / 关终端: 终止后台步骤 → 卸挂载 → 退出; **不补写进度** (标记已实时落盘) |
| `EXIT` | 幂等兜底清理 (挂载/池/本地源服务/hosts), 不覆盖退出码 |

SIGKILL/断电同样不丢进度; 残留挂载由下次构建 lazy 卸载兜底自愈。

## 9. 查日志

```
tail -f output/log/log_<时间戳>/log    # 控制台只有 spinner, 细节全在日志
```
