# 06 开发扩展与排障

## 1. 修改/新增构建步骤

命名规范 (强制): `chroot/$SPACE_NAME/<功能组>/序号_描述.后缀`, 序号两位数字定顺序,
后缀只能是 `.apt` / `.shell` / `.overlay` (未知后缀显式报错):

```
chroot/ubuntu24/common/3_tools.apt        # 加一个包: 直接追加一个词
chroot/ubuntu24/oem/6_my-customization.shell
chroot/ubuntu24/firefly/2_rules.overlay/etc/udev/rules.d/xx.rules
```

机制约定:

- chroot 内步骤是 **root 身份 + arm64 转译环境**, 写 rootfs 内绝对路径;
  构建期没有 systemd 在跑 (只有 proc/sys/dev 挂载);
- 联网行为都走 apt (do_apt.sh 统一 noninteractive);
- `.shell` 必须自己保证退出码正确, 非 0 即中断构建;
- **优先 .apt, 其次 .shell, 克制使用 .overlay**: 完整功能打成 deb 进 firefly 源,
  overlay 只放纯静态文件 (配置/规则/资源), 目录内路径必须与 rootfs 根对齐。

## 2. 新增功能组

1. 建目录 `chroot/ubuntu24/<新组>/`, 按上文规范加步骤;
2. 在 `config/<profile>` 的 `DO_LIST` 里按需位置插入组名 (顺序=执行序);
3. DO_LIST 里的组名必须有对应目录, 否则构建显式报错。

## 3. 新增配置 profile

1. 复制近似的 `config/ubuntu24_*` 为新文件 (纯环境变量);
2. 改 `PACKAGE_NAME` / `SPACE_NAME` / `DO_LIST` / `SOURCE_LIST_FILE` / `IMAGE_NAME`;
3. `./build.sh config` 确认新配置出现在菜单并选择;
4. 新基础包放入 `base-package/` (文件名与 PACKAGE_NAME 一致);
5. **更新 `aidocs/profiles.md` §2 表格** (文档维护义务, 见 AGENTS.md)。

## 4. 自编译包工作流 (src_deb 子模块)

```
# 0. 拉齐子模块
git submodule update --init --recursive

# 1. 进子模块改源码 (如 firefly-binary_deb 下的包目录)
cd src_deb/firefly-binary_deb
./build.sh ffmisc                    # dpkg -b 直接打 deb

# 2. 让构建用上: 把 deb 按 reprepro 规则放进本地仓库
#    src_deb/firefly-reprepro/firefly-ubuntu-repo/ 并重建索引
#    构建期本地源加速会原样提供它 (URL/签名不变)

# 3. 子模块内 commit + push, 再把父仓库的子模块指针一并提交
```

注意:

- 构建入口每次会 `git submodule update --remote src_deb/firefly-reprepro`
  同步到远端最新 —— 本地裸改动会被覆盖, **先在子模块内 commit**;
- `.apt` 里写包名即可, pin 优先级 1001 保证 firefly 版包优先于同名 Ubuntu 包;
- 想改流程本身 (lib.sh 的 trap/快照/打包等) 属"架构性修改",
  **必须同一任务内同步更新 aidocs/** (规则见仓库 AGENTS.md)。

## 5. 调试技巧

```
sudo ./build.sh resume               # 交互选起点, 之前的步骤复用快照不重跑
tail -f output/log/log_<ts>/log      # 每步细节
sudo chroot output/btrfs_mnt/work /bin/bash   # 进构建现场 (见 05 §3)
cat /etc/ffgo/ffver                  # 产物对应哪次提交 (仓库根 git rev-parse HEAD 前 10 位)
```

- 改了第 N 步**之前**的步骤内容, 必须 resume 从第 N 步 (或更早) 跑,
  否则复用的旧快照不含新改动 (机制不做内容指纹检测, 契约靠人遵守);
- 改 lib.sh 后建议先用 `ubuntu24_clean` (最快) 验证流水线, 再跑完整配置;
- 想放弃进度从头构建: 删除 `.build_progress` 后重跑 `sudo ./build.sh` (清空快照池)。

## 6. 排障速查

| 现象 | 处理 |
| --- | --- |
| base 第一步失败, 日志 `Failed to take /etc/passwd lock: Invalid argument` | 宿主 qemu 太旧, 升级到 >= 8.x (见 01 §5); 别用 systemd-sysusers 假体 hack |
| 启动即报 `端口 80 已被占用` | 杀占用进程, 或 config 加 `export LOCAL_FIREFLY_REPO=0` (走外网, 慢) |
| 进度标记非法/失配 (多行/旧格式/步骤不在序列) | 按报错指引: 删 `.build_progress` 重跑; 换过 config 或改过步骤名时用 `resume` 重选起点 |
| 报"进度快照缺失" | 快照被手动删过: 删 `.build_progress` 全量重建, 或 resume 选更早的有快照步骤 |
| 报"有进程占用 work 下挂载点" | `sudo fuser -vm output/btrfs_mnt/work/dev` 找到进程结束之; WSL2 可 `wsl --shutdown` 后重跑 (一般 busy 已被 lazy 卸载自愈) |
| 镜像体积异常大 | apt 缓存 bind-mount 没在打包前卸载 → 确认构建走完了 do_clean |
| submodule 拉取失败 | 构建 sudo 运行时 git 以 $SUDO_USER 身份执行, 检查该用户 ssh key 对 git.t-firefly.com 的权限 |
| base-package 缺失 | 基础包不入 git, 按 PACKAGE_NAME 自备放到 base-package/ |
| 报"功能组目录不存在" | DO_LIST 与 chroot/$SPACE_NAME/ 下实际目录不一致, 二者对齐 |
| 磁盘占用高 | 快照池 output/btrfs_pool.img (稀疏, 占用=base+各步差量); `clean-pool` 释放; 构建成功后池保留属预期 |

## 7. 历史包袱提示 (kylin 线)

`chroot/kylin/` 仍残留 qemu 4.2.1 时代的 systemd-sysusers "echo 假体" hack
(`kylin/base/1_system-user.shell` 替换, `kylin/last/1_fix-system-user.shell` 还原)。
宿主 qemu >= 8.x 后不再必要但尚未删除; 改 kylin 构建时注意, Ubuntu 路径已清理。
