# 01 环境准备与基础骨架

## 1. 这一阶段你将理解

- ubuntu-base 是什么: Canonical 官方发布的"最小可启动骨架", 不是源码, 是最小 rootfs 成品;
- 构建 rootfs 为什么不需要"发行版源码": 发行版 = 包索引元数据 + 二进制包仓库,
  apt 拉包组装即可, 逐包源码编译既不现实也无必要;
- 骨架里已有什么、缺什么 —— 缺的正是后面每一章要补的东西。

## 2. 宿主依赖

```
qemu-aarch64-static --version                     # 必须 >= 8.x (硬要求)
ls /proc/sys/fs/binfmt_misc/ | grep -i aarch64    # 有输出 = 转译通道已注册
sudo apt install -y qemu-user-static e2fsprogs wget   # 缺哪个补哪个
df -h /media/lhj/data                             # 工作区所在盘, 留 15G 以上
```

两个名词:

- **binfmt_misc**: 内核机制, 按可执行文件的魔数 (magic) 决定"交给谁执行";
  aarch64 ELF 被注册为交给 qemu-aarch64-static —— 这就是 x86 CPU 跑 arm64 程序的全部原理;
- **qemu-user-static**: 用户态指令转译器, 不虚拟整机, 只翻译指令, 所以快;
  系统调用仍落在宿主 x86 内核上 (02 §5 会亲手印证)。

## 3. 建工作区

```
W=/media/lhj/data/t-chip/7.code/rootfs/ubuntu26.04/from-scratch
mkdir -p $W/rootfs
```

与 24.04 框架目录平级, 完全独立; rootfs_build 那边保持只读不动。

> 下文所有 `$W` 都指这个工作区。换终端要重设一次, 或直接用绝对路径。

## 4. 下载骨架

```
cd $W
BASE=https://cdimage.ubuntu.com/ubuntu-base/releases/26.04/release
wget $BASE/ubuntu-base-26.04.1-base-arm64.tar.gz      # 约 33M
wget $BASE/SHA256SUMS
sha256sum -c SHA256SUMS 2>/dev/null | grep arm64      # 必须输出 OK
```

- 点版本会更新 (26.04.2/26.04.3...), 文件名跟着换, `Suites: resolute` 永远不变;
- SHA256 校验不是仪式感: 镜像最终烧进产品, 完整性必须机器确认。

## 5. 解包

```
sudo tar -xzf ubuntu-base-26.04.1-base-arm64.tar.gz -C $W/rootfs
```

为什么 sudo: tar 以 root 身份展开才能保住文件属主/权限/dev 下的设备节点;
普通用户解包会把所有文件归到自己名下, 之后 dpkg 会因权限混乱出诡异问题。

## 6. 认识骨架 (本教程第一个理解点)

逐条执行, 每条都在回答一个问题:

```
ls $W/rootfs
# -> bin boot dev etc home lib ... 标准目录树; bin/lib 是指向 usr 同名目录的软链

cat $W/rootfs/etc/os-release
# -> PRETTY_NAME="Ubuntu 26.04.1 LTS", VERSION_CODENAME=resolute
#    后面 apt 源的 Suites 就写它

cat $W/rootfs/etc/apt/sources.list.d/ubuntu.sources
# -> deb822 新格式 (多行字段代替一行一仓库); URIs 指向 ports.ubuntu.com
#    arm64 属于 ports 仓库, 与 x86 的 archive.ubuntu.com 是两个仓库

sudo grep '^root:' $W/rootfs/etc/shadow
# -> root:!:...  感叹号 = root 密码被锁定 (无可登录密码), 这是安全默认
#    以后进系统用普通用户 + sudo, 不开 root (03 §4)

ls $W/rootfs/usr/sbin | head -30
# -> systemd 一族在其中: 骨架有 PID1 (init), 有 apt/dpkg/bash
#    但没有普通用户、没有桌面、没有网络配置层

ls $W/rootfs/lib/modules 2>/dev/null
# -> 不存在。骨架没有内核、没有模块
#    RK 平台内核在 boot 分区单独烧录, rootfs 只带模块 (04 §1 讲分工)
```
