# 核心 CORE-3588 参数

## 1. 老化时打印的温度对应与降频机制

定义位置：`~/7.code/arm64/rockchip/rk3588_6.12.69_sdk/kernel-6.12/arch/arm64/boot/dts/rockchip/rk3588s.dtsi:2790-2929`

> 降频不是"85度+2度滞回"的简单阶梯限频,而是 IPA 电源分配器持续控功率,75°C 就启动,85°C 只是控制目标。

### 1.1 temp0~6 温度区对应

老化日志里的 `temp0~temp6` 就是 `/sys/class/thermal/thermal_zone0~6`(采集脚本 `launch-aging-test.sh` 按 zone 序号命名),共 7 个区:

| zone | 名称 | tsadc 通道 | trip | 典型温度(老化中) |
|---|---|---|---|---|
| temp0 | **soc_thermal** | ch0 | 75°C passive / 85°C passive / 115°C critical | 84~85 ← 唯一管降频的区 |
| temp1 | bigcore0-thermal | ch1 | 仅 115°C critical | 84~85 |
| temp2 | bigcore1-thermal | ch2 | 仅 115°C critical | 84~85 |
| temp3 | littlecore-thermal | ch3 | 仅 115°C critical | 83~84 |
| temp4 | center-thermal | ch4 | 仅 115°C critical | 83 |
| temp5 | gpu-thermal | ch5 | 仅 115°C critical | 82 |
| temp6 | npu-thermal | ch6 | 仅 115°C critical | 82~83 |

除 soc_thermal 外,其余 6 个区没有任何 passive trip(限频 trip),只有 115°C critical 保护。

### 1.2 降频链路(IPA)

`soc_thermal` 三个 trip(`rk3588s.dtsi:2797-2814`):

```dts
threshold: 75000  passive   /* IPA 电源分配器启动点 */
target:    85000  passive   /* PID 控制目标 */
soc_crit: 115000  critical  /* 触发关机 */
sustainable-power = <2100>; /* 整区热预算 2.1W */
```

cooling-maps(`rk3588s.dtsi:2816-2837`)在 target 上挂 4 个 cooling 器件,各 contribution=1024:

| cooling 器件 | 对应 cpufreq/devfreq | opp 范围 |
|---|---|---|
| cpu_l0 | policy0 (A55×4, cpu0-3) | 408M~1.8G |
| cpu_b0 | policy4 (A76×2, cpu4-5) | 1200M~2.4G |
| cpu_b2 | policy6 (A76×2, cpu6-7) | 1200M~2.4G |
| gpu | fb000000 (Mali-G610) | 300M~1G |

**npu 不在任何 cooling-map 里** —— npu 频率是 devfreq 自己按负载选的档,与热限频无关。

governor:`CONFIG_THERMAL_DEFAULT_GOV_POWER_ALLOCATOR=y`(.config:3619),soc_thermal 跑 IPA(power allocator),不是 step_wise。

IPA 机制(`drivers/thermal/gov_power_allocator.c`):

- `trip_switch_on` = 第一个 passive trip(75°C),`control_temp` = 最后一个 passive trip(85°C);
- 每轮发放功率 ≈ `sustainable_power + P项 + I项`,clamp 到 [0, max_allocatable](gov_power_allocator.c:252-291);
- P 项 = k_p × (85 − 当前温度),k_pu = 2×2100/10 = 420mW/°C、k_po = 210mW/°C(:171-174)。

### 1.3 为什么 85°C 以下也在降频

1. **IPA 在 75°C 就开始工作**:温度过 threshold 后内核持续做功率分配,不是到 85 才动手;
2. **预算 2100mW 远小于满载请求**(四 A55 + 四 A76 + GPU 全速要 8~15W)→ 全部按比例砍频;
3. **越接近 85°C 限得越紧**:84°C 时误差只剩 1°C、修正量很小,发放量 ≈ 2.1W 本身;一旦过 85°C,误差变负、P 项倒扣,限得更死。内核就是"贴着 85°C 反复蹭线";
4. **policy0 的 408↔1608 来回摆是 PID hunting**:小核砍到最低后功耗骤降、预算腾给大核,下一轮又回调,加上调频切换延迟,8~12s 一条的采样抓到不同相位。属于 IPA 稳态震荡,正常。

### 1.4 老化日志判读(2026-11-05, LGA-3588L-MINI)

判定是否降频的两条铁证:

1. **policy0 = 408000**(opp 表最低一档),cpu_load=100% 时只有 thermal cooling 会压到最低档(governor 调频不会);
2. **GPU 300~400M @ 84% 负载**:gpu 节点 `upthreshold = <30>`(`rk3588s.dtsi` gpu@fb000000),负载过 30% 正常应冲 1GHz,被按住 = cooling-map 在限。

不算降频的:npu 恒 800M(devfreq 自选档);RK1828-0/1 cpu 1000 / npu 850 全程没动,其 `WARNING` 只是 rknn-smi 对协处理器自身温度(84°C)的健康标志。

### 1.5 安全线

- 各区 **115°C critical** → 内核 orderly 关机;
- tsadc 硬件 `rockchip,hw-tshut-temp = <120000>`(CRU 模式直接复位,`rk3588s.dtsi:7666`);
- 85°C 只是**控制目标**不是危险值,散热按"满载稳在 85°C 附近"设计,老化贴着 85 跑是设计内常态。

调它的方向(固件/散热层,公共脚本不动):改 dts 的 `target` 温度、`sustainable-power`(板级 override)重编 kernel;临时排查可把 `thermal_zone0/policy` 切 `user_space`(不建议老化时用);要降温走散热(风扇/导热垫),IPA 必然控温在 target 附近,频率低是手段不是问题。

工艺：8nm LP

| CPU | 4×Cortex-A76 @2.4GHz + 4×Cortex-A55 @1.8GHz |

| NPU | 6 TOPS，3 核（INT4/INT8/INT16/FP16） |
| 解码 | 8K@30 H.265/VP9/AV1，可拆 32 路 1080p@30 并行 |
| 编码 | 8K@30 H.264/H.265 |

| 存储 | eMMC（HS400） |
