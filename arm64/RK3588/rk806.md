## 1. RK806 概述

RK806 是 RK3588/RK3588S 官方配套 PMIC,提供:

| 电源类型 | 数量 | 枚举(见 rk806.h:284-307) |
|---|---|---|
| DCDC(支持双相并联,10 路 ID) | DCDC1~DCDC10 | `RK806_ID_DCDC1 = 0` |
| NLDO(内建 LDO) | NLDO1~NLDO5 | `RK806_ID_NLDO1` |
| PLDO(高性能 LDO) | PLDO1~PLDO6 | `RK806_ID_PLDO1` |

两个方案选择(SDK 提供 dtsi 模板):

- **single**: `rk3588-rk806-single.dtsi` — 一颗 RK806,SPI2 CS0,节点标签 `rk806single`
- **dual**: `rk3588-rk806-dual.dtsi` — 两颗 RK806 级联,同一 SPI2 总线 CS0/CS1,节点 `rk806master@0` / `rk806slave@1`(dual.dtsi:14 `num-cs = <2>`、:320 slave 节点)

接口模式:`rk806-spi.c` / `rk806-i2c.c` 两个后端,suspend/resume/shutdown 钩子都挂同一套 core 函数:

- `rk806-i2c.c:47` — `DEFINE_SIMPLE_DEV_PM_OPS(rk806_i2c_pm_ops, rk806_core_suspend, rk806_core_resume)`
- `rk806-spi.c:136` — 同上
- shutdown:`rk806-spi.c:133` / `rk806-i2c.c:51` 调 `rk806_core_shutdown()`

单颗 RK806 的 21 路(10 DCDC + 5 NLDO + 6 PLDO)不够驱动整个 RK3588 平台时,大电流核心电轨(CPU 大核、NPU、GPU 独立供电)由外挂 **RK8602/RK8603**(I2C 接口 DCDC)补充,例如 `rk3588-firefly-rk806-single.dtsi:22-56`:`vdd_cpu_big0_s0`(rk8602@42)、`vdd_cpu_big1_s0`(rk8603@43)、`vdd_npu_s0` 等。

## 2. SoC 与 PMIC 的硬件连接(四类信号)

以 single 方案(rk3588-rk806-single.dtsi:10-27)为例:

```
RK3588                          RK806
──────                          ─────
SPI2 (200MHz clk, 1MHz 传输) ──► SPI 接口(CS0)      ← 寄存器读写通道,系统活跃时才可用
GPIO0_A7 ◄────────────────────── INT(低电平有效)     ← PMIC 中断(按键/欠压/过温等)
GPIO0_A2 (sleep1) ─────────────► PWRCTRL1            ← 睡眠握手,硬件自动电平
GPIO0_A3 (sleep2) ─────────────► PWRCTRL2(可选)
GPIO0_C1 (sleep3) ─────────────► PWRCTRL3(可选)
GPIO0_C2 (sleep4)               (参考设计接 PWRCTRL,板级可挪作他用)
GPIO0_C3 (sleep5) / GPIO0_D6 (sleep6)  同上
```

**关键点:这是一套不依赖 CPU 的硬件睡眠握手。** 系统 S3 睡眠时 CPU、SPI 总线全部停摆,RK806 的电压切换只能靠 PWRCTRL 输入脚上的电平变化触发,由 PMIC 内部状态机自主完成。

### 2.1 SoC 侧 SLEEP 输出引脚

`rk3588s-pinctrl.dtsi:1977-1996` 的 `pmic` 节点(`pmic_pins` 组,被 rk806 节点引用):

| 引脚 | func | 信号 | 配置 |
|---|---|---|---|
| GPIO0_A7 | 0(GPIO) | pmic_int_l | pull_up(中断输入) |
| GPIO0_A2 | 1 | pmic_sleep1 | pull_none |
| GPIO0_A3 | 1 | pmic_sleep2 | pull_none |
| GPIO0_C1 | 1 | pmic_sleep3 | pull_none |
| **GPIO0_C2** | **1** | **pmic_sleep4** | pull_none |
| GPIO0_C3 | 1 | pmic_sleep5 | pull_none |
| GPIO0_D6 | 1 | pmic_sleep6 | pull_none |

要点:

1. **func=1 是硬件复用输出**,不是 GPIO。切过去之后引脚电平由 SoC PMU 状态机(深睡时由 ATF 逻辑)控制,内核从不写这个 pad 的电平。
2. `&omit-if-no-ref/` 修饰:没人引用 `pmic_pins` 时整组不编译。
3. GPIO0_C2 的其它复用功能:func2 = HDMI HPDIN m1、func3 = PWM4 m0(见 pinctrl-rockchip.c:973/1191 的 muxroute 表),func0 是 GPIO。
4. U-Boot 侧**没有**引用 pmic_pins(u-boot 全部 rk3588 dts 无此引用),所以进内核前这些脚保持上电默认(GPIO 功能)。

### 2.2 SLEEP 信号的"使能/来源"配置机制

内核把配置经 SIP 调用传给 ATF,ATF 在睡眠状态机里驱动 SLEEP 引脚:

- 驱动:`drivers/soc/rockchip/rockchip_pm_config.c:665-675`,DT 属性 `rockchip,sleep-pin-config`(2 个 u32)→ `sip_smc_call(SLEEP_PIN_CONFIG, [0], [1])`,`SLEEP_PIN_CONFIG = 0x0b`(include/linux/rockchip/rockchip_sip.h:117)
- 位定义:`include/dt-bindings/suspend/rockchip-rk3588.h`:
  - `RKPM_SLEEP_PIN0_ACT_LOW`(BIT0)= GPIO0_A2、`PIN1_ACT_LOW`(BIT1)= GPIO0_A3(官方头文件只给 PIN0/PIN1 标注了 GPIO 编号)
  - 每根 SLEEP 线可配"来源",即**哪个电源域断电时输出有效电平**:
    `VD_NPU / VD_GPU / VD_BIGCORE0 / VD_BIGCORE1 / VD_DSU / VD_VCODEC / VD_DDR / LP_DEEP_LP / SFT_EN(软件强制)`
  - `RKPM_SLEEP_PIN0_SRC(n) ~ PIN5_SRC(n)`:6 根线各占 4bit,拼在 24bit 里 → 正好对应 `sleep_pin_config[2]` 两个 u32 的布局
- 若 DT 没写 `rockchip,sleep-pin-config`(rk3588s.dtsi:2768 的 rockchip-suspend 节点只有 `sleep-mode-config` 和 `wakeup-config`),则全部 SRC=0,该 SLEEP 线不承担任何电源域的睡眠通知。
- 相关睡眠模式位:`RKPM_SLP_PMIC_LP`(BIT17,通知 PMIC 进入低功耗模式)、`RKPM_SLP_ARMOFF_LOGOFF` 等,见同一头文件。

### 2.3 PMIC 侧 PWRCTRL1~3 引脚(PMIC 自己也是 pinctrl 设备)

RK806 内部还有一个 pinctrl 设备(`drivers/pinctrl/pinctrl-rk806.c`),把自己的 3 根控制脚暴露成可配置 pin:

- 引脚名(rk806.h / pinctrl-rk806.c:101-109):`gpio_pwrctrl1` / `gpio_pwrctrl2` / `gpio_pwrctrl3`
- 每脚 6 个功能(pinctrl-rk806.c:112-150,`pin_fun0~5`),与寄存器枚举 `enum rk806_pwrctrl_fun`(rk806.h:357-365)一致:

| function | 值 | 含义 |
|---|---|---|
| pin_fun0 | PWRCTRL_NULL_FUN | 无功能 |
| pin_fun1 | PWRCTRL_SLP_FUN | 睡眠触发(进 sleep 状态) |
| pin_fun2 | PWRCTRL_POWOFF_FUN | 触发 PMIC 关机 |
| pin_fun3 | PWRCTRL_RST_FUN | 触发复位 |
| pin_fun4 | PWRCTRL_DVS_FUN | DVS 电压切换触发 |
| pin_fun5 | PWRCTRL_GPIO_FUN | 当普通 GPIO 用 |

- 板上对它的典型用法(mainline 风格板子如 coolpi-cm5.dtsi:365):把 PWRCTRL1 配成 null(`rk806_dvs1_null: pins="gpio_pwrctrl1"; function="pin_fun0"`),避免睡眠引脚被误触发。
- dual 方案里 slave 的 PWRCTRL 配置状态定义在 rk3588-rk806-dual.dtsi:357-434(`pinctrl_slave_rk806` 节点,rk806_slave_dvs1_null / dvs1_slp / dvs1_pwrdn / dvs1_rst / dvs2_* / dvs3_*),slave 节点本身**不引用 SoC 侧 pmic_pins**(只有 master 引用)。

### 2.4 每路电源"听谁指挥"的寄存器

`enum rk806_vsel_ctr_sel`(rk806.h:373-378):

| 值 | 含义 |
|---|---|
| CTR_BY_NO_EFFECT | 该路电压不受任何控制脚影响 |
| CTR_BY_PWRCTRL1 | PWRCTRL1 电平变化时切到 sleep/DVS 电压 |
| CTR_BY_PWRCTRL2 | 同上,PWRCTRL2 |
| CTR_BY_PWRCTRL3 | 同上,PWRCTRL3 |

内核 suspend 时经 `BUCK1_VSEL_CTR_SEL + i`、`PLDOx_VSEL_CTR_SEL` 寄存器逐路写入(rk806-core.c:1000-1043)。

## 4. 睡眠(S3)机制详解 —— 内核侧

### 4.1 suspend 流程中 RK806 做的事

```
echo mem
  └► PM 核心 suspend
      └► 各驱动 suspend ...
      └► rk806_core_suspend(rk806-core.c:1050)      [I2C/SPI 驱动 pm_ops 挂载]
          ├ disable_irq(rk806->irq)                  /* 睡眠期间不再处理 PMIC 中断 */
          ├ enable_irq_wake(rk806->irq)              /* INT 脚作为唤醒源 */
          └ rk806_configure_sleep_mode()             /* 写"睡眠电压切换"寄存器(见 4.2) */
      └► rockchip_pm_config / SIP → ATF
          └► CPU 断电、PMU 状态机翻转 SLEEP1~6 电平(纯硬件)
              └► RK806 PWRCTRL 脚感知电平变化
                  └► PMIC 内部自主把 CTR_BY_PWRCTRLx 的电轨切到 sleep 电压 / 按序关断
唤醒: 中断/RTC/... → ATF 恢复 PMU → resume
      └► rk806_core_resume(rk806-core.c:1069)
          ├ 所有 rail VSEL_CTR_SEL 写回 CTR_BY_NO_EFFECT
          ├ PWRCTRL1/2/3_FUN 写回 NULL_FUN
          ├ enable_irq / disable_irq_wake
```

### 4.2 `rk806_configure_sleep_mode()`(rk806-core.c:989-1047)两条路径

```c
/* 先全部清零 */
PWRCTRL1_FUN = PWRCTRL_NULL_FUN;
所有 rail: BUCK1_VSEL_CTR_SEL+i = CTR_BY_NO_EFFECT;

if (!dvs_control_suspend || !support_dvs_control_suspend) {
    /* 路径 A:DT 没写 dvs-suspend-control-by(绝大多数板子,包括 Firefly 全系)
       → 全部电轨统一挂 PWRCTRL1 一根线 */
    PWRCTRL1_FUN = PWRCTRL_DVS_FUN;
    所有 rail: CTR_BY_PWRCTRL1;
} else {
    /* 路径 B:按 DT 数组精细分配
       - dvs_control_suspend[i]==CTR_BY_PWRCTRL1 的:
           chip_ver & 0x08 ? PWRCTRL_SLP_FUN : PWRCTRL_DVS_FUN(PWRCTRL1 按芯片版本二选一)
       - ==CTR_BY_PWRCTRL2/3 的:分别开 PWRCTRL2/3_FUN = DVS
       - 所有 PLDO:先把 ON_VSEL 拷到 SLP_VSEL(睡眠电压=运行电压)
       - 再逐路写 CTR_BY_xxx */
}
```

含义:**默认方案下整个睡眠电压切换只依赖一根 PWRCTRL 线**。这是分析 sleep4 是否可省的理论依据(见 §6)。

### 4.3 resume 与 shutdown

- `rk806_core_resume`(rk806-core.c:1069-1080):全部 `VSEL_CTR_SEL = CTR_BY_NO_EFFECT`,PWRCTRL1/2/3_FUN 全部回 `NULL_FUN` —— 即运行态下这些硬件触发通道是关闭的,防止误触发。
- `rk806_core_shutdown`(rk806-core.c:1082-1102):
  - 只在 `system_state == SYSTEM_POWER_OFF` 时动作(否则直接 return,普通重启不走)
  - 若启用了虚拟关机(`rockchip_virtual_poweroff_enabled()`,rockchip_pm_config.c 导出)→ 走 `rk806_configure_sleep_mode`(**假关机/低电待机**,为 RTC 定时开机留门)
  - 正常关机:`rk806_shutdown_requence_config`(rk806-core.c:574-599,把 DT `shutdown-sequence` 写入 BUCK1_SEQ / NLDOx_SEQ / PLDOx_SEQ 硬件顺序寄存器)→ 按属性 `shutown_by_pwrctrln` 选 PWRCTRL1(默认)/ 2 / 3 设成 `PWRCTRL_POWOFF_FUN` + `POL_HIGH` 触发硬件关机。

### 4.4 pinctrl 四个可选状态(rk806-core.c:608-660)

`rk806_pinctrl_init()` 会在 rk806 节点的 pinctrl 句柄里查找 5 个状态:

| 状态名 | 缺失时 | 用途 |
|---|---|---|
| `default` | 仅打印 "no default pinctrl state" | SDK 只提供这一个(即 pmic_pins) |
| `pmic-power-off` | 置 NULL | 关机时切换引脚态 |
| `pmic-sleep` | 置 NULL | 睡眠时切换引脚态 |
| `pmic-reset` | 置 NULL | 复位时切换引脚态 |
| `pmic-dvs` | 置 NULL | DVS 引脚态 |

**注意**:内核里 `default_st` 只 lookup 不 select;真正的 mux 应用发生在 driver core 的 `pinctrl_bind_pins()`(因为节点写了 `pinctrl-names="default"; pinctrl-0=<&pmic_pins>`)。dmesg 里若看到 `no sleep-setting state` 之类**不是错误**,是正常缺省打印。

## 5. GPIO0_C2(pmic_sleep4)冲突案例 —— Firefly lga-3588l-mini-duo-rk182x

### 5.1 冲突构成

| 设备 | 引脚需求 | 出处 |
|---|---|---|
| `&rk806single` → `pmic_pins` | GPIO0_C2 → func1(pmic_sleep4) | rk3588-rk806-single.dtsi:27 → rk3588s-pinctrl.dtsi:1990 |
| `vcc3v3_sys_ctrl`(gpio-leds) | GPIO0_C2 → func0 GPIO,输出高,`retain-state-suspended` | rk3588-firefly-lga-3588l-mini-duo-rk182x.dtsi:4-15(节点)、:520-524(自己的 pinctrl 状态 `vcc3v3_sys_ctrl_pin`) |

板级包含链:`...duo-rk182x.dts` → `...duo-rk182x.dtsi` → `rk3588-firefly-common.dtsi:16` → `rk3588-firefly-rk806-single.dtsi` → `rk3588-rk806-single.dtsi`(rk806single 引用 `pmic_pins`)→ 冲突成立。
同为 Firefly 的 aio-3588l-qua-rk182x 也一样;aio-3588sg 等未用 C2 的板子不冲突。

### 5.2 为什么没有任何内核报错 —— pinctrl 非 strict 的静默抢占

`drivers/pinctrl/pinmux.c:113-143` `pin_request()` 两道属主检查:

```c
if ((!gpio_range || ops->strict) && desc->mux_usecount && strcmp(desc->mux_owner, owner))
        → "pin already requested by ..."(mux 冲突检查)
if ((gpio_range || ops->strict) && desc->gpio_owner)
        → "pin already requested by ..."(gpio 冲突检查)
```

**rockchip pinctrl 没有设置 `.strict`**(pinctrl-rockchip.c 中无 `strict` 字样,false),于是:

| 请求类型 | gpio_range | 检查1(mux属主) | 检查2(gpio属主) | 结论 |
|---|---|---|---|---|
| GPIO 请求(gpiod_get) | 非 NULL | **跳过** | 查 | 抢到 mux 属主已存在的脚也不报错 |
| 设备 pinctrl 状态应用 | NULL | 查 | **跳过** | 抢到 gpio 属主已存在的脚也不报错 |

→ **两个设备谁后 probe 谁赢,dmesg 全程无告警**。设备 pinctrl 状态由 `pinmux_enable_setting()`(pinmux.c:414)以 `setting->dev_name` 为属主逐 pin `pin_request`,失败也只 dev_err_probe 一次,pinctrl_bind_pins 不拦截 probe。

### 5.3 实际后果

- gpio-leds(root 节点平台设备)通常**先** probe;rk806 是 SPI 子设备(需等 spi2 驱动)**后** probe → C2 在 rk806 probe 后**静默切成 SLEEP4**:
  - LED 框架认为灯是开的,实际 pad 已不受 GPIO 控制(写 DR 寄存器无效);
  - 睡眠/唤醒时 pad 电平随 PMU 状态机变化 → vcc3v3_sys 使能电平不受控、`retain-state-suspended` 失效。
- 反之 rk806 先上,则 gpio-leds 的 gpiod_get "成功"但同样写不动 pad。

### 5.4 注释/移除 pc2 的影响面分析

**安全(对本板)**:

1. S3 降压握手不走 C2:板上无 `dvs-suspend-control-by` → 走 §4.2 路径 A,全部电轨只听 **PWRCTRL1**(接 sleep1/GPIO0_A2,仍在组内)。本板 C2 接的是 vcc3v3_sys 的 MOS 门,不可能同时接 PWRCTRL,硬件上已排除。
2. PMIC 中断是 GPIO0_A7;唤醒走 GPIO 控制器(`RKPM_GPIO_WKUP_EN`),均与 C2 无关。
3. U-Boot 不配置此组,移除后 C2 保持 GPIO 功能,启动行为一致。
4. 板上未配 `rockchip,sleep-pin-config`,sleep4 原本就没承担任何电源域通知。
5. PMIC 侧对"没有触发"的反应是**维持现状**(无触发 ≠ 反向动作),不会因少了 sleep4 而误关电源。

**风险(对其它板)**:`rk3588s-pinctrl.dtsi` 是 **SoC 级共享文件**,`pmic_pins` 被 30+ 板引用(rk3588-evb1、rock-5b、coolpi、orangepi、nanopc-t6、edgeble、**rk3588-rk806-dual.dtsi** 等)。若某板硬件真的把 SLEEP4 接到 PWRCTRL2/3 或外部 DCDC 控制脚,在这里注释会导致那路电源的睡眠动作永不触发 → **睡眠功耗升高、该轨睡眠中保持开启**(不崩机,但属隐性回归)。

### 5.5 推荐修复:板级整组替换(不动共享文件)

pinctrl 组不能部分覆盖,板级定义完整替身并改引用:

```dts
/* rk3588-firefly-lga-3588l-mini-duo-rk182x.dtsi */
&rk806single {
    pinctrl-0 = <&pmic_pins_no_sleep4>;
};

&pinctrl {
    pmic-no-sleep4 {
        pmic_pins_no_sleep4: pmic-pins-no-sleep4 {
            rockchip,pins =
                <0 RK_PA7 0 &pcfg_pull_up>,    /* pmic_int_l */
                <0 RK_PA2 1 &pcfg_pull_none>,  /* pmic_sleep1 */
                <0 RK_PA3 1 &pcfg_pull_none>,  /* pmic_sleep2 */
                <0 RK_PC1 1 &pcfg_pull_none>,  /* pmic_sleep3 */
                <0 RK_PC3 1 &pcfg_pull_none>,  /* pmic_sleep5 */
                <0 RK_PD6 1 &pcfg_pull_none>;  /* pmic_sleep6 */
        };
    };
};
```

验证:

```bash
# 1. C2 归属
cat /sys/kernel/debug/pinctrl/pinctrl-rockchip-pinctrl/pinmux-pins | grep " pin18 "
# 期望:pin 18 (gpio0-18) 被 leds/gpiod 持有,IOMUX 为 gpio 功能

# 2. LED 可控性
echo 0 > /sys/class/leds/vcc3v3_sys/brightness; 量 C2 应变低
echo 255 > /sys/class/leds/vcc3v3_sys/brightness; 量 C2 应变高

# 3. 睡眠往返(唤醒后做功能/功耗回归)
echo mem > /sys/power/state
```

## 6. U-Boot 侧行为(补充)

- U-Boot 的全部 rk3588 dts **没有引用 pmic_pins**,不做 SLEEP 引脚 mux;RK806 只做电源初始化(`u-boot/drivers/power/pmic/rk8xx.c`)。
- `rk8xx.c:372-431` `rk8xx_suspend()`:RK806 走"清 PWRCTRL_CONFIG0/1 FUN → 全部 VSEL_CTR_SEL 清 → PWRCTRL0 重使能 + 全部 VSEL_CTR_SEL=PWRCTRL1"的流程(与内核 §4.2 路径 A 同构);RK817/RK809 则是配 SYS_CFG3 的 sleep 脚(active high)。
- 因此进内核前 C2 一定是 GPIO 态;冲突窗口只存在于内核 probe 期间(§5.3)。

## 8. 要点清单(TL;DR)

1. `pmic_pins` = int(GPIO0_A7)+ sleep1~6(A2/A3/C1/C2/C3/D6),func=1 是 **PMU 硬件输出**,内核只 mux 不控电平。
2. SLEEP 电平由 ATF/PMU 状态机在 S3 期间翻转,配置经 `rockchip,sleep-pin-config` → SIP `0x0b`;不配 = 无电源域来源。
3. RK806 收到 PWRCTRL 电平变化后**硬件自主**切电轨:内核 suspend 时写好 `PWRCTRLx_FUN` + 每路 `VSEL_CTR_SEL`。
4. 默认(无 `dvs-suspend-control-by`)**只用 PWRCTRL1 一根握手**;省掉 sleep4/5/6 不影响标准 S3。
5. RK806 自己还有个 pinctrl 设备(`pinctrl-rk806.c`),管 `gpio_pwrctrl1~3`(fun0=null/1=slp/2=pwrdn/3=rst/4=dvs/5=gpio)。
6. rockchip pinctrl **非 strict**,多设备抢同一脚**静默后赢**,排查引脚异常务必查 debugfs `pinmux-pins` 而不是只看 dmesg。
7. 改 SoC 级 pinctrl dtsi 影响全树 30+ 板;板级冲突用**整组替换 `pinctrl-0`** 解决。
8. U-Boot 不碰 SLEEP 组,冲突窗口只在内核 probe 期间。
