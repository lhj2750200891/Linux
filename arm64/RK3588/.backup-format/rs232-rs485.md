# RS232 / RS485 串口适配笔记

## 1. RK3588 UART 全景与选型

RK3588 有 uart0~uart9 共 10 路 UART, RS232/RS485 本质就是
"普通 UART + 板载电平转换芯片":

- RS232: UART TTL 电平 → MAX3232 类转换芯片 → ±12V RS232 电平
- RS485: UART TTL 电平 → MAX3485 类转换芯片 → 差分 A/B 总线

设备树侧只配 UART 复用组。RS485 的关键差异是**收发方向 (DE/RE) 怎么处理**:
- 收发器自动换向型 (Firefly 板全部如此): 设备树零额外配置, 纯 UART 使能
- GPIO 显式方向控制型 (robotic-evb): 加 rs485-de-gpios 等三个属性

内核配置 (defconfig 已开):

```
CONFIG_SERIAL_8250=y
CONFIG_SERIAL_8250_DW=y           # Designware 8250 (RK3588 UART)
```

RS485 属性属于 8250 核心通用支持, 无私有驱动。

## 2. UART 引脚复用组速查 (已核实 rk3588s-pinctrl.dtsi)

| 复用组 | RX | TX | 说明 |
|---|---|---|---|
| uart0m2 | GPIO4_A4 | GPIO4_A3 | q/sjd4: RS232 |
| uart1m1 | GPIO1_B7 | GPIO1_B6 | q/itx: RS485; jd4: RS232 |
| uart3m2 | GPIO4_A6 | GPIO4_A5 | sjd4: RS485 |
| uart5m0 | GPIO4_PD5 | GPIO4_PD4 | 与 can0m1 同引脚, 二选一 |
| uart5m1 | GPIO3_PC5 | GPIO3_PC4 | q: RS232 第二路; 与 can2m0 同引脚二选一 |
| uart6m1 | GPIO1_A0 | GPIO1_A1 | jd4: RS485 |
| uart7m1 | GPIO3_PC1 | GPIO3_PC0 | l-qua: BT (见 wifi-bt 模块) |
| uart8m0 | GPIO4_PB1 | GPIO4_PB0 | robotic-evb: RS485_1 |
| uart9m2 | GPIO3_D4 | GPIO3_D5 | SG: BT (见 wifi-bt 模块) |

带流控的组另有 xxx_ctsn / xxx_rtsn (如 uart9m2_ctsn=GPIO3_D3,
uart9m2_rtsn=GPIO3_D2), 用于 BT 等高速场景。

## 3. 方式一: RS232 — aio-3588q / sjd4 / jd4

### 3.1 硬件连接 (q 板双 RS232 为例)

```
RS232_0 (uart0m2):
  RX ====> GPIO4_A4
  TX ====> GPIO4_A3
  经 MAX3232 类芯片到 DB9/端子

RS232_1 (仅 q 板, uart5m1):
  RX ====> GPIO3_PC5
  TX ====> GPIO3_PC4
```

sjd4: RS232 = uart0m2 一路; jd4: RS232 = uart1m1 一路, 写法相同。

### 3.2 设备树配置

参考: rk3588-firefly-aio-3588q.dtsi (FF_RS232)

```
&uart0 {
	status = "okay";
	pinctrl-names = "default";
	pinctrl-0 = <&uart0m2_xfer>;
};

/* q 板第二路 */
&uart5 {
	status = "okay";
	pinctrl-names = "default";
	pinctrl-0 = <&uart5m1_xfer>;
};
```

要点:
- 纯 RS232 不需要任何额外属性, 使能 + 引脚组即可
- 注意引脚组没被 CAN 等其他模块占用 (uart5m1 与 can2m0 同引脚)

## 4. 方式二: RS485 自动换向 (无方向脚) — aio-3588q / itx / sjd4 / jd4

### 4.1 硬件连接

```
q/itx 板 (uart1m1):
  RX ====> GPIO1_B7
  TX ====> GPIO1_B6
  收发器 (板载自动换向型, DE/RE 由芯片内部时序自管理) → A/B 差分总线

sjd4 (uart3m2): RX=GPIO4_A6, TX=GPIO4_A5
jd4 (uart6m1):  RX=GPIO1_A0, TX=GPIO1_A1
```

### 4.2 设备树配置

参考: rk3588-firefly-aio-3588q.dtsi (FF_RS485) — 就是普通 UART, 完整代码:

```
&uart1 {
	pinctrl-0 = <&uart1m1_xfer>;
	status = "okay";
};
```

sjd4/jd4 换成对应 uart 节点与引脚组, 写法一样。

要点:
- Firefly 板的 RS485 收发器选的是自动换向型号, DE 脚不需要软件管理,
  所以 dtsi 里没有任何 rs485-* 属性
- 这类收发器靠发送数据时的摆幅自动切方向, 小数据量可靠;
  若实测高波特率连续发送有丢帧, 硬件上需换带方向脚的方案 (见方式三)

## 5. 方式三: RS485 GPIO 方向控制 (rs485-de-gpios) — robotic-evb-v11

### 5.1 硬件连接

```
RS485_0 (uart0m2):
  RX ====> GPIO4_A4
  TX ====> GPIO4_A3
  DE/RE (收发方向) ====> GPIO1_A6 (高有效)

RS485_1 (uart8m0):
  RX ====> GPIO4_PB1
  TX ====> GPIO4_PB0
  DE/RE ====> GPIO1_A7 (高有效)
```

### 5.2 设备树配置

参考: rk3588-robotic-evb-v11.dtsi

```
&uart0 {
	status = "okay";
	pinctrl-names = "default";
	pinctrl-0 = <&uart0m2_xfer>;

	/* RS485 方向控制 (8250 核心通用属性) */
	rs485-de-gpios = <&gpio1 RK_PA6 GPIO_ACTIVE_HIGH>;   // DE 脚
	linux,rs485-enabled-at-boot-time;                    // 开机即 RS485 模式
	rs485-rts-active-low;   // DE 极性: 高有效发/低有效收的芯片删掉此行
};

&uart8 {
	status = "okay";
	pinctrl-names = "default";
	pinctrl-0 = <&uart8m0_xfer>;

	rs485-de-gpios = <&gpio1 RK_PA7 GPIO_ACTIVE_HIGH>;
	linux,rs485-enabled-at-boot-time;
	rs485-rts-active-low;
};
```

### 5.3 属性说明

| 属性 | 作用 |
|---|---|
| rs485-de-gpios | DE/RE 合并脚的 GPIO, 内核发送时自动置有效, 发完回落 |
| linux,rs485-enabled-at-boot-time | 开机即 RS485 模式, 免应用层 TIOCSRS485 ioctl |
| rs485-rts-active-low | DE 低有效时声明 (按收发芯片手册定) |

- 收发器 DE 与 /RE 分开接时只接 DE 即可 (/RE 可硬件拉死常收)
- 不配 rs485-de-gpios 也可用 UART RTS 脚做方向 (rs485 rts 模式),
  Firefly 板统一 GPIO 方案更直观

## 6. UART 波特率与时钟说明

- RK3588 UART 输入时钟 24MHz (baudclk 分频), 最高支持到 4M 波特率
- 高波特率 (≥1.5M, 如 BT 固件下载) 属于 WiFi/BT 模块内容
  (见 wifi-bt 模块 uart9/uart7 章节)

## 7. 验证测试

```
# 1. 设备节点
ls /dev/ttyS*                     # uart0~uart9 对应 ttyS0~ttyS9
dmesg | grep -i "ttyS"            # 应看到 dw-apb-uart 注册

# 2. RS232 自发自收 (短接 TX-RX)
stty -F /dev/ttyS0 115200 raw -echo
cat /dev/ttyS0 &
echo "hello" > /dev/ttyS0         # 短接时应收到 hello
# 再接 USB 转 RS232 到 PC (注意 RXD/TXD 交叉), 双向应能通

# 3. RS485 对测 (接 USB 转 RS485 到 PC, A/B 不接反, 共地)
stty -F /dev/ttyS1 115200 raw -echo
cat /dev/ttyS1 &
echo "hello485" > /dev/ttyS1      # PC 应收到
# PC 发数据, 板应能收到

# 4. RS485 模式确认 (方式三)
ip -d link 不适用; 8250 RS485 状态在:
stty -F /dev/ttyS0 -a | grep -i rs485
# 或用应用程序 ioctl(TIOCSRS485) 读回

# 5. 方向脚观察 (方式三, 示波器/万用表)
# 发送期间 DE 脚应变高, 发完自动回落, 且回落延时应远小于字间隔

# 常见问题:
# 1. RS485 只能发不能收 (或反之): 方向脚极性错
#    (rs485-rts-active-low 加/删对比), 或自动换向收发器不适合高波特率
# 2. 收到乱码: 波特率/停止位不匹配, A/B 接反也会全噪声
# 3. 多机总线冲突: 没接终端电阻 120R x2, 或某板 DE 常高占用总线
# 4. uart5/can 冲突: uart5m0 与 can0m1、uart5m1 与 can2m0 同引脚, 各二选一
```
