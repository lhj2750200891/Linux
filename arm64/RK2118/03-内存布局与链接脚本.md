# 内存布局与链接脚本

> 核心文件: `bsp/rockchip/rk2118/default_mem_layout.h`(地址表)、`gcc_xip_on.ld.S` / `gcc_xip_off_ddr.ld.S` / `gcc_xip_off_sram.ld.S`

---

## 1. 物理资源总量

| 区域 | 大小 | 基址 |
|---|---|---|
| XIP (SPI NOR 映射窗) | 4MB | 0x11000000 |
| SRAM | 1MB | 0x30200000 |
| DRAM (DDR) | 64MB | 0xA0000000 |

## 2. XIP 布局 (0x11000000, 恰好用满 4MB)

| 分区 | 偏移 | 大小 | 内容 |
|---|---|---|---|
| RKPARTITIONTABLE | 0x11000000 | 64KB | 分区表 |
| IDBLOCK | 0x11010000 | 128KB | loader(双备份) |
| CPU0_TFM | 0x11030000 | 128KB | TF-M secure 固件 |
| CPU1_LOADER | 0x11050000 | 64KB | cpu1 引导 |
| **CPU0_RTT** | 0x11060000 | 256KB | cpu0 RT-Thread(实际代码起点 +0x800 = **0x11060800**,非安全视角 0x01060800) |
| DSP0 | 0x110A0000 | 1MB | HiFi4 DSP0 固件 |
| DSP1 | 0x111A0000 | 1MB | |
| DSP2 | 0x112A0000 | 1MB | |
| CPU1_RTT | 0x113A0000 | 256KB | cpu1 RT-Thread |
| USER_DATA | 0x113E0000 | 128KB | |

`0x800`(2KB)是所有固件的 RESC 头大小(`__FW_MAGIC_SIZE`),CODE ORIGIN 一律 +0x800。

## 3. SRAM 布局 (0x30200000, 1MB)

| 区 | 偏移 | 大小 |
|---|---|---|
| CPU0_TFM | 0x30200000 | 16KB |
| **CPU0_RTT**(数据/堆) | 0x30204000 | 108KB |
| DSP0 | 0x3021F000 | 128KB |
| DSP1 | 0x3023F000 | 384KB |
| DSP2 | 0x3029F000 | 368KB |
| LOG | 0x302FB000 | 16KB |
| SPI2APB buffer | 0x302FF000 | 4KB(链接 ASSERT 必须等于此地址) |

## 4. DRAM 布局 (0xA0000000, 64MB)

| 区 | 偏移 | 大小 |
|---|---|---|
| CPU0_TFM | 0xA0000000 | 1MB |
| **CPU0_RTT**(代码+堆) | 0xA0100000 | 14MB |
| NPU | 0xA0F00000 | 4MB |
| DSP0 | 0xA1300000 | 18MB |
| DSP1 | 0xA2500000 | 8MB |
| DSP2 | 0xA2D00000 | 18MB |
| CPU1_RTT | 0xA3F00000 | 896KB |
| LOG | 0xA3FE0000 | 128KB |

DSP 各核栈 4KB。

## 5. 链接脚本选择(rtconfig.h 宏自动决定)

| 运行形态 | 宏 | 链接脚本 | 代码位置 |
|---|---|---|---|
| XIP(默认) | CPU_RUN_IN_XIP | gcc_xip_on.ld.S | NOR 直接执行 @0x11060800,DATA 在 SRAM,DDR 堆可选 |
| SRAM | CPU_RUN_IN_SRAM | gcc_xip_off_sram.ld.S | recovery 用,全 SRAM |
| DDR | CPU_RUN_IN_DDR | gcc_xip_off_ddr.ld.S | 代码拷入 0xA0100000 执行 |

- CPU1 的 CODE=XIP_CPU1_RTT,DATA=DRAM_CPU1_RTT(系统堆在 DDR)
- secure 变体地址整体 -0x10000000(安全视角)
- Keil 参考 ac6_xip_off.sct(模板值, mainly AC6 调试用)

### 关键段(.ld.S 摘要)

```
.vectors      向量表 + startup_rk2118.o,重映射到 DATA 起始 (__vector_remap__)
.sram.text    必须驻留 SRAM 的代码(HAL/cache/fspi/snor/systick/pm/context_gcc),
              通过 .copy.table 启动时搬运
.text/.rodata 含 finsh FSymTab/VSymTab、rti_fn 自动初始化段
.zero.table/.copy.table   ARMv8-M 风格启动表(清 bss/搬运数据)
.xip_flag     RT_USING_XIP 时写 0x55aaaa55(package_image.py 靠它判定 XIP)
.data/.bss/.heap  在 SRAM;  .stack __STACK_SIZE=0x400 (1KB)
.ddr.heap     CPU0 的 DDR 大堆;  __large_heap = DRAM_NPU 区
__device_start/end = 0x50000000~0x50E00000 (外设)
__log_buffer = SRAM_LOG;  __spi2apb_buffer = SRAM_SPI2APB
```

## 6. 运行时内存(MPU + 堆)

`board_base.c: rt_hw_board_init()` 配置 MPU:
- region0 code / region1 data / region2 device (0x50000000-0x50DFFFFF) / uncache heap / region4 DDR ext_mem / region5 spi2apb buffer

堆初始化(`rt_memory_heap_init`):
- **CPU0**: 系统堆在 SRAM (`__sram_heap`),DDR 通过 rt_memheap 对象 "ddr" 扩展
- **CPU1**: 系统堆直接在 DDR

## 7. 分区表文件对照

| 文件 | 用途 | 格式 |
|---|---|---|
| `board/<板>/setting.ini` | Firmware.img(NOR 车载)分区 | `[UserPartN] Name/Type/PartOffset/PartSize`(单位 512B 扇区;NIDB@0x80、TFM@0x180 固定) |
| `board/<板>/parameter.txt` | update.img(GPT)分区 | RK CMDLINE 串 + `FIRMWARE_VER: x.y.z` |
| `board/<板>/package-file` | update.img 内容清单 | 每行 `分区名  文件路径` |
| `board/<板>/part.txt` | mkparameter.py 输入 | `name=0x大小` / `name=grow` |

分区类型:0x2=IDBlock、0x100=TFM、0x200=RTT、0x400=DSP、0x800=root/rkstudio FS。
规则:**userdata 必须最后一个分区**;spi nor 64KB 对齐、spi nand 256KB 对齐且留坏块余量;OTA 需 A/B 双份分区。
