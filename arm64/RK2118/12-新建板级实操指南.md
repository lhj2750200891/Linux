# 实操:新建自己的板级 firefly-rk2118g-evb

> 目标:从零建立一个自己的板级目录 `board/firefly_rk2118g_evb`,编译、烧写、点亮,并纳入 git 管理
> 模板:`board/evb1_v20`(SPI NAND + RK2118G + DDR + CLK_CONFIG2,与你手上的板完全同源)
> 所有命令都在 `<SDK>/bsp/rockchip/rk2118` 下执行(下文用 `$BSP` 表示)
> 完成后你将拥有一块:代码归属清晰、版本号独立、可随意魔改而不污染官方板卡的自己的板子

---

## 0. 先理解:这个 SDK 里"一块板"是什么

一块板 = **一个目录 + 两处注册**,共 3 个挂钩点:

| 挂钩点 | 作用 |
|---|---|
| `board/<板名>/` 目录 | 板级代码(board.c/iomux.c)和打包文件(defconfig/parameter.txt/package-file) |
| `board/Kconfig` | 在 "Board Type" choice 里加一个 `RT_USING_BOARD_XXX` 选项 |
| `board/<板名>/SConscript` | `DefineGroup(..., depend=['RT_USING_BOARD_XXX'])` —— 选了板,板级 .c 才编译 |

外层 `board/SConscript` 会**自动扫描**所有子目录,不用改。打包文件(parameter.txt / package-file)以路径传入 build.sh,不需要注册。

整个流程 = 复制目录 → Kconfig 加项 → SConscript 改 depend → defconfig 切板型 → 编译验证。

---

## Step 1:复制模板目录

```bash
cd $BSP        # bsp/rockchip/rk2118
cp -r board/evb1_v20 board/firefly_rk2118g_evb
ls board/firefly_rk2118g_evb/
# 应看到: board.c board.h cpu1_defconfig defconfig defconfig_recovery
#         iomux.c iomux.h package-file parameter.txt part.txt SConscript
```

> 模板选择原则:和你的 flash 类型一致。SPI NAND → evb1_v20;SPI NOR → evb;eMMC → evb_emmc。
> 你手上的板是 NAND,选 evb1_v20 没错。

## Step 2:在 board/Kconfig 注册新板

编辑 `board/Kconfig`,在 Board Type choice 里(`RT_USING_BOARD_EVB3_V10` 之后)插入:

```kconfig
    config RT_USING_BOARD_FIREFLY_RK2118G_EVB
        bool "Enable firefly rk2118g evb board"
        select RT_USING_DDR
```

注意三点:
- 选项名格式必须是 `RT_USING_BOARD_<大写板名>`(SConscript depend 要引用它)
- RK2118G 带 DDR,所以 `select RT_USING_DDR`(模板里的 G 系板都这么写)
- 保持缩进风格(4 空格),和其它条目对齐

## Step 3:改新板 SConscript 的 depend

编辑 `board/firefly_rk2118g_evb/SConscript`,把:

```python
group = DefineGroup('BoardConfig', src, depend = ['RT_USING_BOARD_EVB1_V20'], CPPPATH = CPPPATH)
```

改成:

```python
group = DefineGroup('BoardConfig', src, depend = ['RT_USING_BOARD_FIREFLY_RK2118G_EVB'], CPPPATH = CPPPATH)
```

## Step 4:切换三个 defconfig 的板型选择

defconfig 是纯文本,直接替换(**不要用 menuconfig,你环境里它有 bug**,见文末坑①):

```bash
cd $BSP
# cpu0 主配置
sed -i 's|CONFIG_RT_USING_BOARD_EVB1_V20=y|CONFIG_RT_USING_BOARD_FIREFLY_RK2118G_EVB=y|' \
    board/firefly_rk2118g_evb/defconfig
sed -i 's|# CONFIG_RT_USING_BOARD_EVB1_V20 is not set|# CONFIG_RT_USING_BOARD_FIREFLY_RK2118G_EVB is not set|' \
    board/firefly_rk2118g_evb/defconfig

# cpu1 配置(同样两行 sed,把上面命令的文件名换成 cpu1_defconfig)
sed -i 's|CONFIG_RT_USING_BOARD_EVB1_V20=y|CONFIG_RT_USING_BOARD_FIREFLY_RK2118G_EVB=y|' \
    board/firefly_rk2118g_evb/cpu1_defconfig
sed -i 's|# CONFIG_RT_USING_BOARD_EVB1_V20 is not set|# CONFIG_RT_USING_BOARD_FIREFLY_RK2118G_EVB is not set|' \
    board/firefly_rk2118g_evb/cpu1_defconfig

# recovery 配置(同上,文件名换成 defconfig_recovery)
sed -i 's|CONFIG_RT_USING_BOARD_EVB1_V20=y|CONFIG_RT_USING_BOARD_FIREFLY_RK2118G_EVB=y|' \
    board/firefly_rk2118g_evb/defconfig_recovery
sed -i 's|# CONFIG_RT_USING_BOARD_EVB1_V20 is not set|# CONFIG_RT_USING_BOARD_FIREFLY_RK2118G_EVB is not set|' \
    board/firefly_rk2118g_evb/defconfig_recovery
```

验证(每个文件都应只剩 FIREFLY 的 =y,且 `=y` 和 `is not set` **不能同时有效**——只要确认没有 `CONFIG_RT_USING_BOARD_EVB1_V20=y` 残留即可):

```bash
grep -n "BOARD" board/firefly_rk2118g_evb/defconfig | grep -i "evb1_v20\|firefly"
# 期望: 只有 "# CONFIG_RT_USING_BOARD_EVB1_V20 is not set" 和
#       "CONFIG_RT_USING_BOARD_FIREFLY_RK2118G_EVB=y"
```

顺带把固件版本号改成自己的(打包时 genfwver.py 会写进固件,OTA/启动日志里可见,用于识别"这是我的板子第一版"):

```bash
sed -i 's|FIRMWARE_VER: 1.0.0|FIRMWARE_VER: 0.0.1|' board/firefly_rk2118g_evb/parameter.txt
```

## Step 5:首次编译 + 烧写验证(cpu0 单核,最快)

```bash
cd $BSP
export RTT_EXEC_PATH=<SDK>/prebuilts/gcc/linux-x86/arm/arm-gnu-toolchain-13.2.Rel1-x86_64-arm-none-eabi/bin

./build.sh board/firefly_rk2118g_evb/package-file rtt0     # 只编 cpu0
./mkimage.sh board/firefly_rk2118g_evb/package-file        # 打出 Image/rtt0.img
```

编译中 `scons --menuconfig` 步骤可能报 AttributeError——**无视**(它崩了不影响,后面的 `--useconfig` 会用 .config 生成 rtconfig.h),只要最后 `scons: done building targets` 即可。

验证配置真的生效:

```bash
grep "RT_USING_BOARD_FIREFLY" rtconfig.h
# 期望: #define RT_USING_BOARD_FIREFLY_RK2118G_EVB
```

烧写(进 maskrom:按住 MASKROM 键 + 按 RESET):

```bash
sudo ../tools/upgrade/upgrade_tool db ./rkbin/rk2118_db_loader.bin
sudo ../tools/upgrade/upgrade_tool wl 0x2200 ./Image/rtt0.img
```

串口验收(SYS Debug,1500000 8N1):

```
FIRMWARE_VER: 0.0.1          ← 你的版本号!看到它说明新板固件在跑
```

## Step 6:整包编译 + 完整烧写

```bash
./build.sh board/firefly_rk2118g_evb/package-file        # 全部固件 + 打包 → Image/update.img
```

烧 update.img(`uf` 会连 loader 一起,分区全部刷新):

```bash
sudo ../tools/upgrade/upgrade_tool db ./rkbin/rk2118_db_loader.bin
sudo ../tools/upgrade/upgrade_tool uf ./Image/update.img
```

串口完整验收清单:
- [ ] `FIRMWARE_VER: 0.0.1`
- [ ] `mount root_a fs[elm] on / success`(root 正常)
- [ ] 三个 DSP `Hello RK2118 dsp0/1/2`
- [ ] `msh >` 可交互,`help` 命令齐全

到这里:**新板级已完整建立并跑通**。后面的修改都在自己的目录里做,不会弄脏官方板。

## Step 7:纳入 git

```bash
git status                                 # 新目录应为 untracked
git add bsp/rockchip/rk2118/board/Kconfig
git add bsp/rockchip/rk2118/board/firefly_rk2118g_evb/
git status                                 # 确认没有把 build/ .config rtconfig.h 加进来(.gitignore 已排除)
git commit -m "[bsp] rockchip: rk2118: add firefly rk2118g evb board"
```

> 注意:SDK 根的改动(tftp 补丁、lzma wrapper 思路等)是**另一回事**,和板级分开提交。
> 不确定时 `git status` 看清楚再 add,不要 `git add -A`。

## Step 8:之后个性化自己的板子(按需)

| 想改什么 | 改哪里 | 注意 |
|---|---|---|
| 引脚复用(接了新外设) | `iomux.c` | 对照 RK2118G Datasheet 的 IO 矩阵,注意和其它功能复用冲突 |
| 板级初始化(时钟/电源/器件上电) | `board.c` | 模板的 aw85805/es8388/es7202/tas5805m codec 探测都在 board.c,没有的器件会打 not found,无害 |
| 分区大小/增删分区 | `part.txt` → `mkparameter.py board/firefly_rk2118g_evb/part.txt 0x0`(nand)→ 结果贴回 parameter.txt;package-file 同步 | userdata 必须最后;nand 256KB 对齐、小分区多留 1 block |
| 换 HIFI4 demo | defconfig 里 `HIFI4_PROJECT=...` | 改完存回 defconfig |
| 根分区用 littlefs | defconfig 加 `CONFIG_RT_ROOT_PARTITION_USE_LITTLEFS=y` | 仅 SPI NOR 方案常用,nand 模板保持 FAT |

每改一步的迭代循环:**改 → `./build.sh board/firefly_rk2118g_evb/package-file rtt0` → `./mkimage.sh board/firefly_rk2118g_evb/package-file` → 烧 rtt0 → 看串口**。

## 常见坑(都是这一路上真实踩过的)

1. **menuconfig 起不来**(AttributeError: menuconfig has no attribute '_main'):你机器上的 RT-Thread Env 工具(`~/.env`)版本旧,同名模块抢了 kconfiglib 的菜单实现。绕过:全程用 defconfig 文本编辑 + build.sh/useconfig 流程(本指南即如此)。根治:升级 Env 工具。
2. **rtconfig.h 是生成物**:永远不要手改 rtconfig.h、不要把 .config 当配置源——**defconfig 才是源头**,build.sh 每次都会用它覆盖 .config 再生成 rtconfig.h。
3. **改了 defconfig 却"没生效"**:defconfig 里同一条目出现 `=y` 和 `is not set` 两行时,两行都要处理(Step 4 的两条 sed 就是干这个的)。
4. **分区超限**:改代码后固件变大,打包报 `Packing Error: file length is larger than part size` → 增大 parameter.txt 里对应分区 PartSize,并把**后面所有分区的偏移**顺移。
5. **cpu1/recovery 忘了切板型**:三个 defconfig 都要改(Step 4),否则 cpu1 还在按旧板型编译——代码相同时无症状,分叉时才爆雷。
6. **烧写没反应**:USB Device 口(烧写线)插着时,HOST/DEVICE 模拟开关切到 DEVICE 侧;烧写用 `upgrade_tool`,平时调试拔线。maskrom 进入 = 按住 MASKROM 键 + 按 RESET。
7. **版本号是最快的"刷没刷对"判据**:每次改版把 FIRMWARE_VER 或启动 banner 递增,串口一眼确认。

## 最终目录结构(完成后)

```
board/firefly_rk2118g_evb/
├── board.c / board.h        # 板级初始化(逐步魔改)
├── iomux.c / iomux.h        # 引脚复用
├── defconfig                # cpu0 配置(源头)
├── cpu1_defconfig           # cpu1 配置
├── defconfig_recovery       # recovery 配置
├── package-file             # update.img 内容清单
├── parameter.txt            # 分区表 + FIRMWARE_VER
└── SConscript               # depend 已指向你的板
board/Kconfig                # 多了一个 choice 项
```
