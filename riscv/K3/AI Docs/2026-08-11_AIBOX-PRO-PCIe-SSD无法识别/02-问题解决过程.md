# 问题解决过程：AIBOX-PRO PCIe SSD 无法识别

- 解决日期：2026-08-11
- 环境：SpacemiT K3、Firefly AIBOX-PRO、Linux 6.18.3、PCIe 0 x4、NVMe SSD 119.2 GiB

## 问题现象

AIBOX-PRO 的设备树已启用 K3 `pcie0_rc`、`phy0` 和 `phy1`，并按原理图配置为 x4。插入 NVMe SSD 并冷启动后，`lsblk` 中只有系统盘 `sda`，没有 NVMe 设备；`lspci -nn`、`lspci -tv` 和 `/sys/bus/pci/devices/` 也均为空。

运行时设备树检查显示：

```text
/soc/pcie@80000000/status        okay
/soc/pcie@80400000/status        disabled
/soc/phy-pcie@81d00000/status    okay
/soc/phy-pcie@81e00000/status    okay
```

因此控制器和 PHY 节点本身已经生效，但 PCIe 端点没有完成链路建立和枚举。

## 最终根因

GPIO50 同时被两个设备树功能使用：

- `vcc3v3-pcie` 将 GPIO50 配置为 PCIe SSD 3.3V 电源使能。
- UART6 的 `uart6_0_cfg` 将 GPIO50 配置为 UART6 CTS。

启动时 UART6 对应的 `d4017500.serial` 先申请了 GPIO50，导致 PCIe 固定电源节点应用 pinctrl 失败并回滚：

```text
k1-pinctrl d401e000.pinctrl: pin GPIO_50 already requested by d4017500.serial; cannot claim for vcc3v3-pcie
k1-pinctrl d401e000.pinctrl: error -EINVAL: pin-50 (vcc3v3-pcie)
k1-pinctrl d401e000.pinctrl: error -EINVAL: could not request pin 50 (GPIO_50) from group pcie-pwr-en-cfg.pcie-pwr-en-pin
reg-fixed-voltage vcc3v3-pcie: Error applying setting, reverse things back
```

PCIe SSD 的 3.3V 电源未正常使能，因此 PCIe Link 无法建立，最终表现为 `lspci` 和 `lsblk` 均看不到 SSD。

## 关键排查过程

1. 静态检查设备树，确认 `FF_PCIE1` 宏实际启用的是原理图对应的 `pcie0_rc`，使用 `phy0 + phy1`、`num-lanes = <4>`，与仓库中其他 K3 x4 配置一致。
2. 编译并反编译最终 DTB，确认 `pcie0_rc`、`phy0`、`phy1` 状态为 `okay`，`pcie1_rc` 保持 `disabled`，排除宏展开或 DTB 语法问题。
3. 板端检查运行时设备树，结果与源码一致，排除烧录了错误 DTB 的方向。
4. `lspci` 为空，说明问题发生在块设备和 NVMe 驱动之前，应优先检查 PCIe 供电、复位、参考时钟和链路训练。
5. 启动日志明确报告 `vcc3v3-pcie` 无法申请 GPIO50；进一步追踪发现 GPIO50 已被 UART6 CTS 占用，从而确定 GPIO复用冲突是根因。
6. 禁用 `FF_RS485_UART6` 后重新编译、烧录并冷启动，GPIO50 被释放，系统成功识别 NVMe SSD。

## 解决方案

将 `k3-firefly-aibox-pro.dts` 中：

```dts
#define FF_RS485_UART6
```

改为：

```dts
//#define FF_RS485_UART6
```

该修改用于验证并解除 GPIO50 冲突。若产品最终需要同时保留 PCIe SSD 与 UART6 RS485，应为 UART6 新建板级 pinctrl，只配置实际使用的 TX、RX、RTS 等引脚；在硬件未使用 CTS 时，不要继续申请 GPIO50。

- 枚举验证：


- 文件系统：`/dev/nvme0n1p1`，FAT32，容量约 119.2 GiB。
- 验证工具：安全的文件级 `nvme_fio_test.sh`，测试文件大小 2 GiB。
- 完整性验证：fio CRC32C 校验通过。
- 顺序读取：fio 测试通过。

## 可复用经验

- PCIe SSD 不枚举时，先检查 `lspci` 和控制器启动日志；`lspci` 为空时不要直接从文件系统或 NVMe 上层驱动开始排查。
- 同一个 GPIO 不能同时出现在电源使能节点和外设 pinctrl 中。看到 `already requested by ... cannot claim for ...` 时，应优先追踪引脚所有者。
- 存储读写测试应使用文件系统中的临时文件，避免直接对整块裸盘执行 fio 或 dd；完整性校验与内核错误检查应同时进行。
