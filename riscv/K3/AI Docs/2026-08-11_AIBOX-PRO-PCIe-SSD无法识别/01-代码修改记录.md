# 代码修改记录：AIBOX-PRO PCIe SSD 无法识别

- 解决日期：2026-08-11
- 项目/平台：SpacemiT K3 / Firefly AIBOX-PRO / Linux 6.18.3
- 修改目标：解除 UART6 与 PCIe SSD 电源使能之间的 GPIO50 复用冲突，并用安全的文件级 fio 测试验证 NVMe 读写。

## 修改概览

| 文件 | 位置 | 修改目的 |
| --- | --- | --- |
| `arch/riscv/boot/dts/spacemit/k3-firefly-aibox-pro.dts` | `FF_RS485_UART6` 功能宏 | 暂停启用会占用 GPIO50 的 UART6 RS485 配置，使 GPIO50 可作为 PCIe 3.3V 电源使能。 |
| `arch/riscv/boot/dts/spacemit/nvme_fio_test.sh` | 新增测试脚本 | 在已有文件系统中安全创建临时文件，执行完整性、顺序读取和随机混合读写测试。 |

## 修改 1：禁用冲突的 UART6 RS485 配置

文件：`arch/riscv/boot/dts/spacemit/k3-firefly-aibox-pro.dts`  
位置：板级功能宏定义 `FF_RS485_UART6`

修改前：

```dts
#define FF_RS485_UART6
```

修改后：

```dts
//#define FF_RS485_UART6
```

修改说明：

启用 `FF_RS485_UART6` 后，UART6 使用 `uart6_0_cfg`：

```dts
pinmux = <K3_PADCONF(48, 2)>, /* uart6 tx */
         <K3_PADCONF(49, 2)>, /* uart6 rx */
         <K3_PADCONF(50, 2)>, /* uart6 cts */
         <K3_PADCONF(51, 2)>; /* uart6 rts */
```

其中 GPIO50 同时被 PCIe 固定电源节点用作 3.3V 使能：

```dts
gpio = <&gpio K3_GPIO(50) GPIO_ACTIVE_HIGH>;
```

UART6 驱动先占用 GPIO50，导致 `vcc3v3-pcie` 固定电源节点申请引脚失败。禁用该功能宏后，GPIO50 被释放，PCIe 3.3V 电源能够正常使能，SSD 随后完成 PCIe/NVMe 枚举。

该修改会同时停用 UART6 RS485。若后续仍需使用 RS485，应根据原理图新建仅包含实际使用引脚的板级 UART6 pinctrl，例如在 CTS 未连接时去掉 GPIO50，而不是永久关闭 UART6。

## 修改 2：新增安全的 NVMe fio 测试脚本

文件：`arch/riscv/boot/dts/spacemit/nvme_fio_test.sh`

修改前：

```text
文件不存在。
```

修改后关键逻辑：

```bash
DEVICE="${1:-/dev/nvme0n1p1}"
SIZE_MIB="${2:-2048}"
RUNTIME_SECONDS="${3:-60}"

DEVICE_TYPE="$(lsblk -ndo TYPE "${DEVICE}" 2>/dev/null || true)"
if [[ "${DEVICE_TYPE}" != "part" ]]; then
	printf 'Error: %s is not a partition. Refusing raw-disk testing.\n' "${DEVICE}" >&2
	exit 1
fi

TEST_FILE="${MOUNT_POINT}/.nvme_fio_test_${TIMESTAMP}_$$.bin"
```

完整性验证工作负载：

```bash
run_fio integrity_verify \
	--name=integrity_verify \
	--filename="${TEST_FILE}" \
	--size="${SIZE_MIB}M" \
	--rw=write \
	--bs=128k \
	--direct=1 \
	--ioengine=libaio \
	--iodepth=16 \
	--verify=crc32c \
	--verify_fatal=1 \
	--do_verify=1 \
	--end_fsync=1 \
	--group_reporting
```

修改说明：脚本拒绝对整块裸盘执行 fio，只允许在分区文件系统中创建临时测试文件；测试结束后删除文件，并检查测试期间新增的 NVMe/PCIe 内核错误日志。

## 最终结果

- `/proc/device-tree/soc/pcie@80000000/status` 为 `okay`。
- `phy-pcie@81d00000`、`phy-pcie@81e00000` 均为 `okay`。
- 系统成功识别 `nvme0n1`，容量约 119.2 GiB。
- fio CRC32C 完整性验证通过。
- fio 顺序读取测试通过。
- 60 秒 4 KiB、70% 读/30% 写随机混合测试通过：读取约 68.6 MiB/s，写入约 29.4 MiB/s。
- 测试期间未检测到关键 NVMe/PCIe 内核错误，临时测试文件已正常清理并卸载文件系统。
