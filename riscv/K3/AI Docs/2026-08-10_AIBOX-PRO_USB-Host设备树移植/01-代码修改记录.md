# 代码修改记录：AIBOX-PRO USB Host设备树移植

- 解决日期：2026-08-10
- 项目根目录：`/media/lhj/data/t-chip/7.code/spacemiT/K3_Linux_SDK_6.18/bsp-src/linux-6.18`
- 平台：SpacemiT K3 / Firefly AIBOX-PRO / Linux 6.18.3
- 参考板：Firefly AIBOX
- 外部Hub：Genesys Logic GL3523 USB 3.0 Hub
- USB2数据选择器：SGM7227YMS
- 验证设备：USB 2.0 U盘
- 最终结果：用户确认USB Host测试正常，U盘能够正常识别和读写

## 1. 修改目标

将AIBOX原本用于Type-C的K3 USB3 Port A信号迁移到AIBOX-PRO的固定USB Host接口：

- USB 3.0 SuperSpeed差分信号直接连接GL3523上行端口。
- USB 2.0 D+/D-经过SGM7227选择后连接GL3523上行端口。
- GPIO100打开USB口5V供电。
- GPIO77控制GL3523复位。
- GPIO118把SGM7227切换到USB Hub路径。
- USB控制器固定为Host模式。
- 避免UART1复用GPIO118，防止RS232配置破坏USB Host。

## 2. 硬件连接和最终电平

| 功能 | K3信号/引脚 | GPIO | Linux配置 | 运行时电平 | 说明 |
| --- | --- | ---: | --- | --- | --- |
| USB口5V使能 | `USB30_VCC5V0_EN` | 100 | fixed regulator | 高 | 打开USB Host 5V电源开关 |
| GL3523复位控制 | `USB30_HUB_RST` | 77 | GPIO hog | **低** | 低电平使Q8截止，GL3523的`HUB_RESET#`由R118拉高，释放复位 |
| USB2路径选择 | `USB_SEL` | 118 | GPIO hog | **高** | SGM7227选择HSD2，即GL3523 USB2上行通道 |
| USB2 D+ | `USB0_DP` | 专用PHY | `usb3_porta_u2phy` | 差分 | 经过SGM7227连接GL3523 `USB0_D_P` |
| USB2 D- | `USB0_DN` | 专用PHY | `usb3_porta_u2phy` | 差分 | 经过SGM7227连接GL3523 `USB0_D_N` |
| USB3 RX- | `USBSS0_RX_N` | 专用PHY | `usb3_porta_u3phy` | 差分 | 连接GL3523上行SuperSpeed端口 |
| USB3 RX+ | `USBSS0_RX_P` | 专用PHY | `usb3_porta_u3phy` | 差分 | 连接GL3523上行SuperSpeed端口 |
| USB3 TX- | `USBSS0_TX_N` | 专用PHY | `usb3_porta_u3phy` | 差分 | 连接GL3523上行SuperSpeed端口 |
| USB3 TX+ | `USBSS0_TX_P` | 专用PHY | `usb3_porta_u3phy` | 差分 | 连接GL3523上行SuperSpeed端口 |

### 2.1 GPIO77复位极性必须特别注意

GPIO77没有直接连接GL3523的低有效复位脚，而是连接Q8 NMOS栅极：

```text
GPIO77 = 1
  -> Q8导通
  -> HUB_RESET#被拉到GND
  -> GL3523保持复位

GPIO77 = 0
  -> Q8截止
  -> HUB_RESET#由R118上拉到VCC3V3_HUB
  -> GL3523释放复位
```

因此设备树中GPIO77必须配置为`output-low`。把它配置成`output-high`会导致`lsusb -t`只显示xHCI根Hub，看不到任何GL3523下游Hub。

### 2.2 GPIO5共享电压域必须统一

K3 pinctrl驱动中GPIO99～GPIO127共用`IO_PWR_DOMAIN_GPIO5_K3`。本板以下信号都位于该电源域：

- GPIO100：USB 5V使能
- GPIO118：USB_SEL
- GPIO120：UART1_RX
- GPIO121：UART1_TX

UART1硬件原理图确认SoC侧使用`VCC1V8_SYS`，因此该共享域统一配置为：

```dts
power-source = <1800>;
```

不能让GPIO100/118使用3300、GPIO120/121使用1800。K3驱动会配置整个共享I/O电源域，混用会使最后一次应用的pinctrl状态覆盖同域电压配置。

## 6. 修改3：GPIO hog必须放在GPIO控制器下面

文件：`arch/riscv/boot/dts/spacemit/aibox-pro-test.dtsi`

修改前的问题：GPIO hog节点曾被放在根节点`/`下面。`gpio-hog`只有作为GPIO控制器子节点时才会被GPIO核心解析；放在根节点下不会自动驱动目标GPIO。

修改后：

```dts
&gpio {
	pinctrl-names = "default";
	pinctrl-0 = <&usb30_hub_rst_cfg>, <&usb_sel_cfg>;

	usb30-hub-rst-hog {
		gpio-hog;
		gpios = <K3_GPIO(77) GPIO_ACTIVE_HIGH>;
		output-low;
		line-name = "usb30_hub_rst";
	};

	usb-sel-host-hog {
		gpio-hog;
		gpios = <K3_GPIO(118) GPIO_ACTIVE_HIGH>;
		output-high;
		line-name = "usb_sel_host";
	};
};
```

修改说明：

- GPIO77由GPIO控制器在注册时申请并保持低电平。
- GPIO118由GPIO控制器在注册时申请并保持高电平。
- `line-name`便于在板端使用`gpioinfo`确认GPIO是否被正确hog。
- K3 GPIO控制器的`#gpio-cells = <3>`，`K3_GPIO(77)`展开为bank和offset，因此hog中的写法是正确的三单元GPIO描述。

## 7. 修改4：修正GL3523复位极性

```dts
	line-name = "usb30_hub_rst";
```

修改后：

```dts
usb30-hub-rst-hog {
```

## 8. 修改5：USB_SEL固定选择USB Hub路径

文件：`arch/riscv/boot/dts/spacemit/aibox-pro-test.dtsi`

最终代码：

```dts
usb-sel-host-hog {
	gpio-hog;
	gpios = <K3_GPIO(118) GPIO_ACTIVE_HIGH>;
	output-high;
	line-name = "usb_sel_host";

```

修改说明：SGM7227功能表表明选择信号为1时HSD2通道导通。AIBOX-PRO中HSD2连接GL3523的USB2上行D+/D-；选择信号为0会切换到原Type-C/OTG路径，USB 2.0 U盘无法经GL3523枚举。

## 9. 修改6：USB口5V供电

文件：`arch/riscv/boot/dts/spacemit/aibox-pro-test.dtsi`

最终代码：

```dts
/ {
	usb30_vcc5v0_en: regulator-usb30-vcc5v0-host {
		compatible = "regulator-fixed";
		regulator-name = "usb30_vcc5v0_host";
		regulator-min-microvolt = <5000000>;
		regulator-max-microvolt = <5000000>;
		gpios = <&gpio K3_GPIO(100) GPIO_ACTIVE_HIGH>;
		enable-active-high;
		regulator-boot-on;
		regulator-always-on;
		pinctrl-names = "default";

```

修改说明：GPIO100高电平打开USB Host口5V。`regulator-boot-on`和`regulator-always-on`保证启动期间及系统运行时持续供电；`vbus-supply`把该电源与USB3 Port A控制器关联。

## 12. 修改9：消除UART1与USB_SEL冲突

文件：`arch/riscv/boot/dts/spacemit/k3-firefly-aibox-pro.dtsi`

原公共pinctrl组`uart1_1_cfg`包含：

```dts
uart1_1_cfg: uart1-1-cfg {
	uart1-0-pins {
		pinmux = <K3_PADCONF(118, 1)>, /* UART1 RTS */
			 <K3_PADCONF(119, 1)>, /* UART1 CTS */
			 <K3_PADCONF(120, 1)>, /* UART1 RX */
			 <K3_PADCONF(121, 1)>; /* UART1 TX */
	};
};
```

修改前板级UART1引用：

```dts
&uart1 {
	pinctrl-names = "default";
	pinctrl-0 = <&uart1_1_cfg>;
	status = "okay";
};
```

问题：即使用户空间没有启用`CRTSCTS`，pinctrl仍会把GPIO118复用成UART1_RTS，导致GPIO118无法作为USB_SEL保持高电平。

修改后：

```dts
&uart1 {
	pinctrl-names = "default";
	pinctrl-0 = <&uart1_rs232_cfg>;
	status = "okay";
};

&pinctrl {
	uart1_rs232_cfg: uart1-rs232-cfg {
		uart1-rs232-pins {
			pinmux = <K3_PADCONF(120, 1)>,
				 <K3_PADCONF(121, 1)>;
			bias-pull-up;
			drive-strength = <25>;
			power-source = <1800>;
		};
	};
};
```

修改说明：AIBOX-PRO RS232硬件只有RX/TX，不使用RTS/CTS。新组只占GPIO120/121，GPIO118完整保留给USB_SEL。

## 14. 移植到另一套SDK时的最小文件清单

至少同步以下内容：

1. `aibox-pro-test.dtsi`完整文件。
2. `k3-firefly-aibox-pro.dts`中的`FF_USB30_HOST`和include。
3. `Makefile`中的`k3-firefly-aibox-pro.dtb`目标。
4. 如果启用UART1，必须同步两线`uart1_rs232_cfg`，不能继续使用包含GPIO118的`uart1_1_cfg`。
5. 确认目标SDK的`k3.dtsi`仍提供标签：
   - `&gpio`
   - `&pinctrl`
   - `&usb3_porta_u2phy`
   - `&usb3_porta_u3phy`
   - `&usb3_porta`
6. 确认目标SDK中的GPIO宏仍是三单元格式：

```dts
#define K3_GPIO(x) ((x) / 32) ((x) % 32)
```

如果目标SDK的GPIO binding或节点标签不同，不能机械复制，必须按目标SDK调整GPIO描述符。
