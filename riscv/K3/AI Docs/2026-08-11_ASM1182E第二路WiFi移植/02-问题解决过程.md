# 问题解决过程：ASM1182E 第二路 RTL8852BE WiFi 移植

- 解决日期：2026-08-11
- 环境：SpacemiT K3、Firefly AIBOX-PRO、Linux 6.18.3、ASM1182E、RTL8852BE/RTL8852BU WiFi 蓝牙组合模组

## 问题现象

ASM1182E 上游链路和第二下行口均能正常枚举，PCIe 端能够识别 RTL8852BE `[10ec:b852]`，USB 端蓝牙也能正常加载 `btusb` 和 RTL8852BU 固件。

WiFi 固件文件存在且能够被 `rtw89_8852be` 读取，但系统没有生成 `phy0` 或 `wlan0`。驱动日志为：

```text
failed to alloc dma tx rings
failed to alloc pci trx rings
failed to setup pci resource
probe with driver rtw89_8852be failed with error -12
```

## 最终根因

`-12` 为 `ENOMEM`，实际失败点是 `rtw89` 调用 `dma_alloc_coherent()` 分配 PCIe TX descriptor ring。

RTL8852BE 属于需要手动开启 DAC 的芯片。Linux 6.18 的 `rtw89_pci_is_dac_compatible_bridge()` 仅对白名单上游桥启用 36-bit DMA；ASMedia 分支只识别设备号 `0x2806`，未包含本板使用的 ASM1182E `0x1182`。因此 WiFi 位于 ASM1182E 后方时保持默认 32-bit DMA mask。

K3 系统 RAM 从 4 GiB 以上开始，且 K3 配置没有提供普通 `ZONE_DMA32` 内存。32-bit DMA mask 无法覆盖可分配的物理内存，导致启动早期的小尺寸 TX ring 分配也失败。

## 关键排查过程

1. 确认 `vcc3v3_wifi` 开启，WiFi/BT rfkill 均未软阻塞或硬阻塞，排除供电和 DISABLE 管脚问题。
2. `lspci` 显示 ASM1182E 两个下行桥以及 RTL8852BE endpoint，证明 PCIe PHY、参考时钟、复位及第二路差分链路正常。
3. `lsusb` 和蓝牙日志正常，证明 CH344P 扩展 USB 与模组蓝牙部分正常。
4. 固件加载成功但没有无线接口，进一步检查完整 `rtw89` 日志，定位到 TX DMA ring 分配失败和 `-ENOMEM`。
5. 对照 `drivers/net/wireless/realtek/rtw89/pci.c`，确认 ASM1182E 不在 36-bit DMA 上游桥白名单。
6. 对照 K3 内存布局、Kconfig 和 SDK 中 `k3_dc_board.dts` 的 PCIe restricted DMA pool 示例，确定可通过设备树提供 32-bit PCIe DMA 窗口。

`k1-spi ... DMA setup failed (-19)` 属于 SPI 驱动回退 PIO，与 WiFi 无关。`of_irq_parse_pci: failed with rc=-22` 未阻止 MSI/驱动绑定和实际 WiFi 通信，不是本次故障根因。

## 解决方案

受“仅修改 `aibox-pro-test.dtsi`”约束，未修改 `rtw89` 驱动源码，而是在测试 DTS 中：

- 保留 32 MiB `restricted-dma-pool`，CPU 物理地址为 `0x1f0000000`。
- 在 `pcie3_rc` 增加 `dma-ranges`，映射为 PCIe 侧地址 `0x80000000`。
- 通过 `memory-region` 将该 DMA pool 关联到 ASM1182E 所在 PCIe RC。

长期产品化时也可以评估在 `rtw89` 中验证并增加 ASM1182E DAC 兼容支持，从而避免 RC 级 restricted DMA pool；该方向本次未修改、未验证。

## 验证结果

- 验证方法：检查 restricted DMA pool、PCIe 驱动绑定、rfkill、`iw dev`、AP 扫描、NetworkManager 连接、DHCP 和公网 ping。
- 驱动结果：`Kernel driver in use: rtw89_8852be`。
- 接口结果：成功生成 `phy0` 和 `wlan0`。
- 射频结果：可扫描到 2.4 GHz 与 5 GHz AP。
- 网络结果：成功连接 WPA2 AP、获取 IPv4 地址和默认路由，并通过 `wlan0` ping 公网地址，未丢包。
- 隐私处理：验证使用的真实 SSID、密码、MAC 地址和 DHCP 地址未写入归档。

## 可复用经验

- PCIe endpoint 能枚举且固件能加载，不代表驱动一定完成初始化；应继续确认 DMA ring、IRQ、`phy` 和 netdev 是否注册。
- 在物理内存位于 4 GiB 以上的平台，位于 PCIe switch 后方的 32-bit DMA 设备很容易因上游桥白名单或 DMA 地址转换缺失而报 `-ENOMEM`。
- restricted DMA pool 是设备树受限场景下的有效验证方案，但它作用于同一 PCIe RC 下的设备；SSD 与 WiFi 共存时仍应进行并发压力测试。
