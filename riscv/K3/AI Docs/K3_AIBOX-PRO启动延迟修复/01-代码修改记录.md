# 代码修改记录：AIBOX-PRO 启动延迟修复

- 解决日期：2026-08-03
- 项目/平台：SpacemiT K3 Linux SDK 6.18、Firefly AIBOX-PRO-K3、U-Boot 2022.10、ESOS RT24 双 RCPU
- 修改目标：为 `k3-firefly-aibox-pro` 补齐 U-Boot FIT 和 ESOS 双 RCPU 设备树支持，消除错误板型回退及约 12 秒启动等待。

| --- | --- | --- |

## 修改 3：在 U-Boot FIT 中加入 PRO 配置

文件：`bsp-src/uboot-2022.10/board/spacemit/k3/configs/uboot_fdt.its`  
位置：`images` 和 `configurations`

修改前：

```dts
/* images 中最后只有 fdt_14：k3-firefly-aibox-k3.dtb */
/* configurations 中最后只有 conf_14：k3-firefly-aibox-k3 */
```

修改后：

```dts
fdt_15 {
	description = "k3-firefly-aibox-pro.dtb";
	type = "flat_dt";
	compression = "none";
	data = /incbin/("../dtb/k3-firefly-aibox-pro.dtb");
	hash-1 {
		algo = "crc32";
	};
};
```

```dts
conf_15 {
	description = "k3-firefly-aibox-pro";
	loadables = "uboot";
	fdt = "fdt_15";
};
```

修改说明：`board_fit_config_name_match()` 使用 EEPROM 中的 `product_name` 与 FIT configuration 的 `description` 做精确匹配。增加 `conf_15` 后，不再因找不到 PRO 配置而回退到默认 `k3_deb1`。

## 修改 5：将 PRO 双核 DTB 加入 ESOS FIT

文件：`package-src/esos/esos_rt24.its`  
位置：`images` 和 `conf_dual.loadables`

修改前：

```dts
"rcpu0-dtb-aibox-k3", "rcpu1-dtb-aibox-k3", "rcpu0-fw", "rcpu1-fw";
```

修改后：

```dts
rcpu0-dtb-aibox-pro-k3 {
	description = "ESOS Core0 AIBOX-PRO-K3 dtb";
	type = "standalone";
	os = "esos";
	arch = "riscv";
	compression = "none";
	load = <0x1 0xf4a000>;
	entry = <0x1 0xf4a000>;
	data = /incbin/("../output/esos/k3_rt240_firefly_aibox_pro.dtb");
	hash {
		algo = "crc32";
	};
};

rcpu1-dtb-aibox-pro-k3 {
	description = "ESOS Core1 AIBOX-PRO-K3 dtb";
	type = "standalone";
	os = "esos";
	arch = "riscv";
	compression = "none";
	load = <0x1 0xf56800>;
	entry = <0x1 0xf56800>;
	data = /incbin/("../output/esos/k3_rt241_firefly_aibox_pro.dtb");
	hash {
		algo = "crc32";
	};
};
```

```dts
"rcpu0-dtb-aibox-k3", "rcpu1-dtb-aibox-k3",
"rcpu0-dtb-aibox-pro-k3", "rcpu1-dtb-aibox-pro-k3",
"rcpu0-fw", "rcpu1-fw";
```

修改说明：ESOS 从 `0x100e05000` 开始按 `0xC800`（50 KiB）步长扫描 DTB 表。原最后一个槽位为 `0x100f3d800`，因此两个新 DTB 使用连续槽位 `0x100f4a000` 和 `0x100f56800`。两个 PRO DTB 均小于 50 KiB。

## 编译与镜像生成

```bash
make uboot-rebuild MAKE_JLEVEL=8
make esos-dirclean
make esos MAKE_JLEVEL=8
make MAKE_JLEVEL=8
```

`esos-dirclean` 用于清除 Buildroot 中旧的 ESOS 源码和构建标记，避免普通增量构建继续使用缓存。
